# Oilgame — план разработки

Браузерный симулятор добычи нефти с учебным уровнем реализма. Двухфазная
(oil + water) задача на 2D-сетке с возможностью смотреть вертикальные
разрезы. Реализация — TypeScript, рендер — Canvas2D, без фреймворков.

> **Единицы измерения** — полевые метрические (как принято в
> российской нефтянке): давление в атм, проницаемость в мД,
> вязкость в сП, дебит жидкости в м³/сут, дебит нефти в т/сут,
> время в часах. Эти единицы используются **и в коде, и в UI** —
> никаких переводов туда-сюда, чтобы формулы читались как
> в учебнике.

---

## 1. Цель и аудитория

- **Пользователь** учится основам разработки: закон Дарси,
  материальный баланс, ОФП, Бакли-Леверетт, заводнение,
  вытеснение нефти водой, влияние БЗД на дебит.
- **Поведение** — игра, не тренажёр. Можно «поиграть»: поставить
  добывающие и нагнетательные скважины, понаблюдать за фронтом
  вытеснения, посмотреть на обводнённость и КИН.
- **Уровень** — учебный. Физика корректная, но упрощённая
  (двухфазная, изотермическая, без гравитации по вертикали
  на первом этапе; сжимаемость флюидов и породы — через
  эффективный коэффициент `c_t`).

## 2. Решения по проекту (зафиксированы)

### 2.1. Общие

| Параметр | Решение |
|---|---|
| Реализм | Учебный (корректная физика, но упрощённая) |
| Размерность | 2D сверху + разрезы (cross-section) |
| Фазы | Нефть + вода (двухфазная) |
| Стек | Vanilla TypeScript + Canvas2D |
| Хостинг / CI | Только локально, без remote, без GitHub Actions |
| Язык UI | Русский. Технические идентификаторы, JSON-поля, имена файлов — английские |

### 2.2. Физические

- Единая сетка (один пласт, переменная толщина `h(x,y)` в каждой
  ячейке, кросс-секция показывает колонку ячеек).
- IMPES (Implicit Pressure, Explicit Saturation) — классика для
  учебного курса, стабильный при разумном шаге по времени.
- Без гравитации на первом этапе; капиллярное давление —
  опционально (см. §10), по умолчанию `P_c = 0`.
- Многослойность — отложена (см. §10).
- Аквифер (Carter-Tracy) — отложен (см. §10).
- Масштаб времени: 1x = 1 сутки за 1 секунду реального времени.
  Диапазон скоростей: 0.25x, 0.5x, 1x, 2x, 5x, 10x, 30x, 100x.

### 2.3. Единицы измерения (полевые метрические)

| Величина | Единица | Обозначение в коде |
|---|---|---|
| Давление | атм (техническая) | `atm` (1 атм = 0.0980665 МПа) |
| Время | час | `h` (1 ч = 3600 с) |
| Длина, толщина | м | `m` |
| Площадь | м² | `m2` |
| Объём | м³ | `m3` |
| Пористость | доли | `φ` (0..1) |
| Насыщенность | доли | `S` (0..1) |
| Проницаемость | мД | `mD` (1 мД ≈ 9.869e-16 м²) |
| Вязкость | сП | `cP` (1 сП = 1 мПа·с) |
| Плотность | кг/м³ | `kg_m3` |
| Сжимаемость | 1/атм | `atm-1` |
| Объёмный коэф. | м³/м³ | `m3_m3` (reservoir / surface) |
| Дебит жидкости | м³/сут | `m3_d` |
| Дебит нефти (масса) | т/сут | `t_d` |

Время в формулах и при выводе — час. Дата в UI вычисляется
как `startDate + hours · 3600 · 1000` (миллисекунды для `Date`).

## 3. Физика

### 3.1. Сетка и карты

- Регулярная декартова сетка `Nx × Ny` ячеек, шаг `dx = dy` (м).
- Карты на ячейку: `h` (эффективная толщина, м), `φ` (пористость,
  доли), `k_x`, `k_y` (абсолютная проницаемость, мД),
  `S_w0` (начальная водонасыщенность, доли), `P_0`
  (начальное пластовое давление, атм).
- Контур месторождения — булева маска `active(x,y)` (нет потока
  через неактивные ячейки). Гетерогенная толщина `h(x,y)` тоже
  «обрезается» снаружи.
- Внутри `active` можно заложить **зоны** (sandy channel, барьер,
  разлом с нулевой трансмиссибельностью) — это делает историю
  визуально интересной.

### 3.2. Свойства породы и флюидов

- Константы на ячейку: `μ_w`, `μ_o` (сП), `ρ_w`, `ρ_o` (кг/м³),
  `c_w`, `c_o`, `c_r` (атм⁻¹), `B_w`, `B_o` (м³/м³), `k_rw_max`,
  `k_ro_max`, `S_wc`, `S_or`, `n_w`, `n_o`.
- ОФП — модель **Corey** (водо-смачиваемый песчаник):
  ```
  S*     = (S_w - S_wc) / (1 - S_wc - S_or)
  k_rw   = k_rw_max · (S*)^n_w
  k_ro   = k_ro_max · (1 - S*)^n_o
  ```
- `S_w` ограничена `[S_wc, 1 - S_or]` при решении.
- Капиллярное давление — табличная `P_c(S_w)`, по умолчанию `0`
  (пренебрегаем на первом этапе).

### 3.3. Уравнения (в полевых метрических единицах)

**Закон Дарси для каждой фазы** (фаза `α ∈ {o, w}`):
```
q_α [м³/сут] = C_darcy · k[mD] · k_rα · A[м²] · ΔP[атм]
              / (μ_α[cП] · B_α[м³/м³] · L[м])
```
где `C_darcy = 0.0543` — переводной множитель (см. §3.6).
Поток направлен из области высокого в область низкого давления.

**Подвижности** (м³/(сут·мД·м²·атм) → сокращаются):
```
λ_α  = k_rα / (μ_α · B_α)            [сП⁻¹ · м³/м³⁻¹]
λ_t  = λ_o + λ_w                     — полная
f_w  = λ_w / λ_t                     — доля воды в потоке
```

**Уравнение давления** (IMPES, `S_w` фиксирована на шаге):
```
V_p · c_t · ∂P/∂t = ∇·(T · ΔP) + q_t
```
- `V_p = φ · V_bulk` — поровый объём ячейки (м³).
- `c_t = φ·(S_w·c_w + S_o·c_o) + c_r` — полная сжимаемость (атм⁻¹).
- `T` — transmissibility между ячейками (см. §3.7), м³/(сут·атм).
- `q_t = q_o + q_w` — суммарный дебит/приёмистость (м³/сут).
- `∂P/∂t` — производная давления по времени (атм/ч).

**Уравнение насыщенности** (явно, после давления):
```
V_p · ∂S_w/∂t = -∇·(f_w · F_t) + q_w
```
- `F_t = T · ΔP` — полный межъячеечный поток (м³/сут).
- `q_w` — дебит воды в ячейке (м³/сут).
- Схема — **upwind** по знаку `F_t`.

### 3.4. Скважины (Писман)

Для каждой скважины в ячейке `(i,j)`:
```
q_α = J · k_rα / (μ_α · B_α) · (P_cell - P_bh)
```
- `P_bh` — забойное давление (атм), задаётся пользователем.
- `J` — индекс продуктивности/приёмистости (м³/(сут·атм)):
  ```
  J = C_darcy · 2π · k_h · h / (ln(r_e/r_w) + S)
  ```
  где `C_darcy = 0.0543`, `r_w` — радиус скважины (м),
  `S` — скин-фактор.
- **Эквивалентный радиус** Писмана (для изотропной квадратной
  ячейки): `r_e = 0.2 · dx`. Для анизотропной — обобщённая
  формула (см. §3.6).
- **Producer**: BHP < P_cell → добыча; q ≥ 0 при BHP ≤ P_cell.
- **Injector**:  BHP > P_cell → нагнетание; q ≤ 0 (знак по соглашению).
- Лимит по дебиту (`rate limit`) — опционально, для защиты схемы.

### 3.5. Граничные условия

- **No-flow** (закрытый контур) на границе `active`-маски.
- **Аквифер (leaky BC)** — реализован в `PressureSolver` через
  `pAquiferAtm` и `aquiferTransmissibilityFrac`. К каждой
  неактивной ячейке добавляется фиктивная transmissibility
  `tAquiferBase = aquiferTransmissibilityFrac · tAvg` к
  «бесконечной» ячейке с давлением `pAquiferAtm` (см. §10
  «Принятые решения»). Держит `P_avg` стабильным при
  больших отборах; без аквифера маленький field (1×1 км,
  поровый объём ~1.9e6 м³) с типичными rates истощается
  за 10–15 сут.

### 3.6. Вывод переводных множителей

**C_darcy = 0.0543** для полевых метрических единиц:

В СИ: `q [м³/с] = k[м²] · A[м²] · ΔP[Па] / (μ[Па·с] · L[м])`

Переход к полевым метрическим (`k` в мД, `μ` в сП, `ΔP` в атм,
`q` в м³/сут, `t` в ч):
- `k[м²] = k[мД] · 9.869233e-16`
- `μ[Па·с] = μ[сП] · 1e-3`
- `ΔP[Па] = ΔP[атм] · 98066.5`
- `q[м³/с] = q[м³/сут] / 86400 = q[м³/ч] / 24`

Подставляя:
```
q[м³/ч] = k[мД] · 9.869e-16 · A · ΔP[атм] · 98066.5
        / (μ[сП] · 1e-3 · L) · 1/24
```
Множитель: `9.869e-16 · 98066.5 / 1e-3 / 24 ≈ 4.03e-7`.

Но `q[м³/сут] = q[м³/ч] · 24` (а не делить), значит
```
q[м³/сут] = 9.869e-16 · 98066.5 / 1e-3 · k · A · ΔP[атм] / (μ · L)
         = 9.68e-8 · k · A · ΔP / (μ · L)
```

Hmm, это не 0.0543. Перепроверим для радиальной формулы Писмана:
```
q[м³/с] = 2π · k[м²] · h · ΔP[Па] / (μ[Па·с] · ln(re/rw))
```

В полевых:
```
q[м³/сут] = 2π · k[мД] · 9.869e-16 · h · ΔP[атм] · 98066.5
          / (μ[сП] · 1e-3 · ln(re/rw)) · 86400
        = 2π · 9.869e-16 · 98066.5 · 86400 / 1e-3 · k · h · ΔP / (μ · ln(re/rw))
        = 2π · 9.869e-16 · 98066.5 · 86400 · 1e3 · k · h · ΔP / (μ · ln(re/rw))
        = 2π · 0.8366 · k · h · ΔP / (μ · ln(re/rw))
        = 5.256 · k · h · ΔP / (μ · ln(re/rw))
```

Это для **безразмерной формулы без B**. С учётом объёмного
коэффициента `B`:
```
q[м³/сут] = (2π / B) · 5.256 · k · h · ΔP / (μ · ln(re/rw))
         = 33.0 / B · k · h · ΔP / (μ · ln(re/rw))
```

Подожди, это сильно отличается от 0.0543. Где-то ошибка.

Перепроверим с другой стороны. Известная формула (Peaceman, field):
```
q[stb/day] = 0.007082 · k[mD] · h[ft] · ΔP[psi] / (μ[cP] · Bo[rb/stb] · ln(re/rw))
```

Конверсия в метрические:
- `1 ft = 0.3048 m` → `h[ft] = h[m] / 0.3048`
- `1 psi = 0.068046 atm` → `ΔP[psi] = ΔP[atm] / 0.068046`
- `1 stb = 0.158987 m³` → `q[stb/day] = q[m³/day] / 0.158987`

Подставляя:
```
q[m³/day] / 0.158987 = 0.007082 · k · (h / 0.3048) · (ΔP / 0.068046)
                     / (μ · Bo · ln(re/rw))
q[m³/day] = 0.007082 · 0.158987 / (0.3048 · 0.068046) · k · h · ΔP / (μ · Bo · ln(re/rw))
         = 0.007082 · 0.158987 / 0.02074 · k · h · ΔP / (μ · Bo · ln(re/rw))
         = 0.007082 · 7.665 · k · h · ΔP / (μ · Bo · ln(re/rw))
         = 0.0543 · k · h · ΔP / (μ · Bo · ln(re/rw))
```

Так вот откуда 0.0543. Я перепутал направление конверсии выше.
Финальная формула:

**Радиальный дебит (Писман) в полевых метрических:**
```
q[м³/сут] = 0.0543 · k[mD] · k_r · h[m] · ΔP[атм]
          / (μ[cP] · B[м³/м³] · ln(re/rw))
```

**Линейная transmissibility (TPFA):**
```
T_ij [м³/(сут·атм)] = 0.0543 · k_harm[mD] · A[м²]
                    / (μ_harm[cP] · B_harm[м³/м³] · Δx[m])
```
где `k_harm` — гармоническое среднее (см. §3.7), `μ_harm`,
`B_harm` — берутся при средней насыщенности между ячейками
(для `μ·B` — аппроксимация восходящим весом по подвижности).

### 3.7. Дискретизация (FVM / TPFA)

Система ячеек `(i,j)`. Для каждой грани `ij → (i±1,j)` или
`(i,j±1)` вводится transmissibility:

```
T_ij = 0.0543 · 2·k_i·k_j / (k_i + k_j) · A / (μ·B·d)
```
- `A = h · min(dx, dy)` — площадь грани (для ортогональной сетки).
- `d` — расстояние между центрами ячеек.
- `μ·B` берётся в восходящем направлении (upstream) по знаку
  `ΔP`, чтобы T был consistent с upwind-схемой для насыщенности.

**Граничные transmissibility** (no-flow на контуре):
`T_ij = 0` для неактивной ячейки.

**Матрица системы** для давления:
```
Σ T_(i,j)→(i',j') · (P_(i',j') - P_(i,j))
  + c_t · V_p / Δt · (P^(n+1)_(i,j) - P^n_(i,j))
  = q_t^(n+1)_(i,j)
```
Система SPD; решается CG с preconditioner Jacobi.

### 3.8. Time stepping (CFL-адаптивный шаг)

**CFL-условие** для явного шага насыщенности:
```
Δt_max = V_p / max_i |F_t,i|
```
где `F_t,i = T_ij · ΔP` — межъячеечный поток (м³/сут).
**Плюс** вклад скважин: `max_i |q_t,i|` (жидкостной дебит
в ячейке со скважиной). Без этого скважины не ограничивают
шаг и могут дать NaN.

**Полный адаптивный шаг:**
```
Δt = min(Δt_max / CFL_target,
         Δt_max_step,        // защита
         Δt_to_next_event)   // например, до BHP-change
```

**Актуальные дефолты** (см. `DEFAULT_SOLVER` в
`defaultParameters.ts`):

| Параметр | Значение | Комментарий |
|---|---|---|
| `cflTarget` | 0.3 | доля порового объёма, «пересекаемая» потоком за шаг (поячеечный CFL) |
| `dtMaxHours` | 20 | ≈ 0.83 сут, верхняя граница шага |
| `dtMinHours` | 0.1 | только «пожелание»: CFL может вернуть меньше. Реальная нижняя граница — `HARD_MIN_HOURS` = 1e-4 ч |
| `pAvgDamping` | 0.35 | доля инкремента материального баланса, применяемая к `P_avg` за подшаг |
| `rateRelaxation` | 0.5 | базовая ω релаксации дебитов |
| `rateChangeTarget` | 0.2 | жёсткий предел изменения дебита за внешний шаг, в долях `cap` |
| `cflPressureFraction` | 0.3 | доля от «запаса» `\|P_avg − BHP\|` на подшаг |
| `pressureMarginFloorAtm` | 0.5 | нижняя граница запаса до BHP, атм |
| `pressureRelaxation` | 0.5 | **legacy (v1)**, в superposition не используется |
| `cgTolerance` | 1e-6 | **legacy (v1)** pressure solver (CG) |
| `cgMaxIterations` | 400 | **legacy (v1)**; достаточно для 50×50 (2500 неизвестных) |
| `historyIntervalHours` | 1 | Запись в history каждый час симуляции |

> Параметры стабилизации (`pAvgDamping` … `pressureMarginFloorAtm`)
> добавлены при исправлении неустойчивости «скачков при добавлении
> скважин»; их смысл — в `AGENTS.md` §3.3 и `docs/parameters.md`.
> Подробности — `core/time/SuperpositionStepper.ts`.

`pressureRelaxation` гасит осцилляции давления при больших
скин-факторах / высокой k:
`P_new = P_old + ω · (P_solved − P_old)`. `ω = 1` — без
релаксации. **В v2 не используется** — оставлен как legacy
рядом с CG-решателем; см. `AGENTS.md` §3.3.

**Частота записи в history** — каждые
`historyIntervalHours = 1 ч` по умолчанию (раньше 24 ч,
уменьшено для более гладких графиков в UI). Конфигурируется.

**Частота перерисовки UI** — каждый кадр, но не чаще `1 / real_dt`
(т.е. 60 Гц). Состояние читается из кеша.

### 3.9. Performance targets

| Сценарий | Сетка | Шаг | Целевое время шага | FPS |
|---|---|---|---|---|
| Учебная (дефолт) | 50×50 | 6 ч | < 5 мс | 60 |
| Средняя | 100×100 | 3 ч | < 20 мс | 60 |
| Большая | 200×200 | 1 ч | < 80 мс | 30 |

- 200×200 — предел для UI на средней машине; выше — нужны

- На сервере CI тесты идут с `--no-ui` режимом, бенчмарк
  измеряет `step()` без `draw()`.

### 4.7. Экономика (опционально, для дашборда)

**Все деньги в USD.**

| Параметр | Значение | Единица |
|---|---|---|
| Цена нефти | 70 USD/bbl | ≈ 440 USD/м³ (surface) |
| Стоимость закачки воды | 3 USD/м³ | нагнетаемой воды |
| OPEX на скважину | 80 тыс. USD/мес | фиксированный + variable |
| CAPEX на скважину | 3 млн USD | бур + обустройство |
| Ставка дисконтирования | 10% годовых | — |
| Плотность нефти (поверхн.) | 850 кг/м³ | для пересчёта м³↔т |
| 1 м³ | 6.29 bbl | — |
| 1 т нефти (поверхн.) | ~7.4 bbl | — |

**Формула NPV** (Net Present Value) — дисконтированная разница
выручки и затрат:
```
NPV = Σ_t CF_t / (1 + r)^t
CF_t = Revenue_t - OPEX_t - CAPEX_t
Revenue_t = q_oil[t] · oil_price · B_o / ρ_oil_surface · dt
          // q_oil в м³/сут (reservoir) → пересчёт в surface m³:
          // surface_m3 = reservoir_m3 / B_o
          // mass_tons = surface_m3 · ρ_surface
          // price = mass_tons · price_per_ton
OPEX_t = Σ_wells (opex_per_well_per_month) · dt_months
```
Где `r = 0.10` — годовая ставка; `t` в годах от старта.

**Внутренняя норма доходности (IRR)** — значение `r`, при котором
`NPV = 0`. Считается методом бисекции.

**Дефолтные пороги** для дашборда:
- Безубыточность при среднем дебите ≥ 50 м³/сут на скважину.
- Окупаемость CAPEX при `NPV > 0` (отображается на графике).
- Бюджет ограничен условно 50 млн USD (можно настраивать).

### 4.8. Алгоритм генерации дефолтного поля

Синтетическое месторождение, с фиксированным seed (воспроизводимо):

```ts
// 1. Базовая решётка пористости (логнормальное распределение)
φ[i,j] = exp(μ_φ + σ_φ · randn()); clamp(0.10, 0.30)

// 2. Связь k с φ (correlation 0.7)
ln(k[i,j]) = a + b · φ[i,j] + σ_k · randn()
// a, b подобраны так, чтобы среднее k = 100 мД

// 3. Эффективная толщина (гладкая карта)
h[i,j] = h_mean + A · cos(2π·x/Lx) · cos(2π·y/Ly)
       + B · exp(-((x - x_c)² + (y - y_c)²) / R²)
// 3-й член = «sandy channel» (утолщение в центре)

// 4. Разлом: линия от (x1, y1) до (x2, y2), T = 0 на этой грани
fault_segment: { p1, p2, throw_m }
  for each cell crossed: mark as barrier, set k_fault = 0

// 5. Контур месторождения
active[i,j] = (in_ellipse(x, y, cx, cy, a, b, angle)) && !on_fault

// 6. Начальное давление (гидростатика)
P_0[i,j] = P_ref + 0.1 · (z_ref - z[i,j])  // 0.1 атм/м

// 7. Начальная насыщенность (равномерная, выше S_wc)
S_w0[i,j] = S_wc + 0.05
```

Параметры генерируются функцией `generateDefaultField(seed=42)`
в `src/data/defaultField.ts`. Возвращает `Reservoir` со всеми
картами. Seed фиксирован — для воспроизводимости тестов.

### 5.2. Архитектурные принципы

1. **Pure core.** `src/core/**` — без побочных эффектов,
   детерминирован (при фиксированном RNG). Все формулы и
   вычисления — в полевых метрических единицах, как в учебнике.
   Тесты `core/**` запускаются под `vitest node`.
2. **`FieldState` — single source of truth.** UI и тесты читают
   состояние через `engine.getState()`. Никто не дублирует
   массивы `P` и `S_w`.
3. **`step()` — чистая функция.** Сигнатура:
   ```ts
   step(state: FieldState, dt: number, controls: Controls): FieldState
   ```
   Внутри IMPES разбит на подшаги: `solvePressure`,
   `solveSaturation`, `applyWells`. Каждый — тестируемый.
4. **EventBus.** UI ↔ Engine ↔ Save — через события
   (`onWellsChanged`, `onStateUpdated`, `onSimError`).
5. **Единицы — полевые метрические, везде.** См. §2.3. `core/units.ts`
   хранит константы (`ATM_PER_PA`, `SEC_PER_HOUR`, `BARREL_PER_M3`,
   `C_DARCY = 0.0543` и т.д.) и **только** для пересчёта
   нефти (м³↔т) и времени (ч↔мс для `Date`). Сами формулы
   Дарси и transmissibility написаны напрямую в полевых
   единицах — никакой «метрической шизофрении» внутри.
6. **Детерминизм.** Все «случайные» величины (генерация
   синтетического поля) принимают `seed` (mulberry32).
   Дефолт — фиксированный seed.
7. **i18n строк UI.** Все видимые пользователю надписи —
   в `src/i18n/ru.json`. Сейчас только RU, но архитектура
   готова к добавлению EN.

### 5.3. Цикл симуляции

```
main loop (requestAnimationFrame):
  if not paused:
    real_dt = clock.realDt()        // 16ms обычно
    sim_dt   = real_dt * speed      // 1x = 1 day / sec
    newState = engine.step(sim_dt)   // несколько подшагов IMPES
    renderer.draw(newState)
    if sim_time crosses a record boundary (24h default):
      history.append(metrics)
      economics.append(cashflow)
```

`engine.step()` — адаптивный шаг: внутри одного `step()`
может быть несколько CFL-подшагов IMPES (каждый ≤ 720 ч),
но извне выглядит как один тик.

### 5.4. Численные детали

- **Pressure solve:** линейная система `T·P = b`, SPD.
  Решатель — **Conjugate Gradient (CG)** с preconditioner Jacobi.
  Сетка 50×50 = 2500 уравнений — решается < 1 мс в браузере.
  Tolerance 1e-6, max 200 итераций.
- **Saturation step:** upwind 1-го порядка по знаку `F_t`.
  Прямое обновление `S_w^{n+1} = S_w^n + dt/V_p·(...)`.
  Кламп к `[S_wc, 1 - S_or]`.
- **CFL:** `Δt_max = V_p / max|F_t|`, target CFL = 1.0.
- **Сглаживание:** без него на старте; TVD при осцилляциях.

### 5.5. Метрики и графики

Снимаются каждый **отчётный интервал** (24 ч симуляции по умолчанию):

**По скважинам** (для каждой):
- `q_o` — дебит нефти (т/сут) = `q_o_reservoir / B_o · ρ_o_surface`
- `q_w` — дебит воды (м³/сут)
- `q_liq` — дебит жидкости (м³/сут) = `q_o_reservoir + q_w`
- `WC` — обводнённость = `q_w / q_liq`
- Накопленные `N_p` (т), `W_p` (м³), `W_i` (м³) с начала.

**По месторождению:**
- `P_avg` — среднее давление (атм)
- `S_w_avg` — средняя водонасыщенность
- `КИН` (recovery factor) = `N_p / OOIP` (OOIP — initial oil in place, т)
- `VRR` — voidage replacement ratio = `W_i / (B_o · (N_p_surface + W_p))`
- `OOIP` = `Σ φ · (1 - S_w0) · V_bulk / B_o · ρ_o_surface`

**UI рисует 6 графиков** в `ChartsPanel` (сетка 2×3,
подписаны на `stateUpdated` из EventBus):
1. `q_o(t)` (т/сут) и `q_w(t)` (м³/сут) — суммарно по месторождению.
2. `WC(t)` (%) — обводнённость.
3. `P_avg(t)` (атм) — среднее пластовое давление.
4. `N_p(t)` (т), `W_p(t)`, `W_i(t)` (м³) — накопленная добыча/закачка.
5. `КИН(t)` (%) и `VRR(t)` (—).
6. `q_o_per_well(t)` (т/сут) — дебит нефти по скважинам.

Дополнительно — **BHP-sparkline** в каждой карточке
скважины в `WellsList` (мини-`Sparkline` с историей
BHP за время симуляции).
(Phase 6) `NPV(t)`, `CF(t)`.

- **Аннотация версии** — `SCHEMA_VERSION = N` в начале файла.
- **Тесты** — `tests/integration/saveMigrations.spec.ts`
  с фикстурами старых версий.
- **Идемпотентность** — повторный прогон не меняет данные.
- **Неудача** — выбрасывает `MigrationError` с указанием
  шага и версии.

### 7.4. Автосохранение

- Каждые **60 секунд реального времени**, если были изменения.
- Через `requestIdleCallback` (или `setTimeout(0)` fallback).
- Хранится в слоте `autosave` (не показывается в UI, всегда
  перезаписывается). Восстанавливается при следующем запуске
  с подтверждением «Восстановить автосохранение?».
- Debounce — повторное сохранение не чаще 1 раза в 30 секунд.

### 7.5. Обработка ошибок

- **Битый файл** (не парсится) — toast: «Файл повреждён,
  не могу загрузить». Кнопка «Восстановить из автосохранения».
- **Несовместимая версия** — toast: «Файл из версии X, нужна
  миграция до Y. Запустите промежуточную версию или
  используйте онлайн-конвертер (ссылка)».
- **Конфликт** (загрузка при непустом поле) — диалог:
  «Заменить текущую конфигурацию?». По умолчанию — отмена.
- **Слоты localStorage** — проверка `JSON.parse` + Zod-схема;
  при несоответствии — игнор с предупреждением в консоль.

## 11. v2: Superposition model (замена IMPES-pressure на аналитику)

> **Решение от 24.08.2026.** Полная замена численного решателя
> давления (CG-IMPES с leaky aquifer) на аналитическую стационарную
> суперпозицию + материальный баланс для дрейфа среднего.

### 11.1. Почему

Текущая IMPES-система:
- Решает 50×50 СЛАУ на каждом шаге (CG, ~5–20 итераций)
- Имеет leaky aquifer (Carter-Tracy) для стабилизации P_avg
- Использует under-relaxation по давлению (ω = 0.5)
- Учитывает well-CFL

Цели рефакторинга:
- **Понятность**: пользователь должен видеть, откуда берётся
  давление в каждой точке (формула, а не «solve A·P=b»).
- **Скорость**: убрать итерации CG.
- **Правдоподобие**: стационарная воронка — классическая
  инженерная модель (Dake, Craft-Hawkins, §2.3). Для учебной
  задачи идеально.
- **Наглядное взаимодействие скважин**: rate одной зависит
  от BHP и положения других — линейная система N×N решается
  мгновенно.

### 11.2. Модель

**Давление (стационарная суперпозиция)** — модуль
`src/core/pressure/Superposition.ts`:

```
P(x) = P_avg + Σ_w [(q_w · μ·B) / (2π·k_eff_w·h_eff_w)] · ln(r_w(x) / R_e_w)
                              для r_w(x) ≤ R_e_w
                            0  для r_w(x) > R_e_w
```

- `q_w > 0` = production (воронка депрессии), `q_w < 0` = injection.
- `k_eff_w`, `h_eff_w` — средние в окрестности радиуса `R_e_w`.
- `R_e_w` — радиус влияния (по умолчанию: половина расстояния
  до ближайшего соседа/границы — «dynamic»).
- Время не входит: воронка мгновенная и стабильная.

**Rates по BHP (линейная система)** — модуль
`src/core/wells/RateSolver.ts`:

Из той же суперпозиции для каждой скважины j:
```
P_bhp_j - P_avg = -Σ_i A_ji · q_i
```
где `A_ji = (μ·B)/(2π·k_i·h_i) · ln(R_e_i / d_ij)`,
`d_jj = r_wj`, `d_ij` (i≠j) — расстояние между скважинами.

Решаем `A · q = (P_avg - P_bhp)`, откуда `q = A^{-1} · (P_avg - P_bhp)`.
Система N×N, N — число скважин (обычно ≤ 10). Метод: Гаусс
с частичным выбором главного элемента. Решается за < 0.1 мс.

**Дрейф P_avg (материальный баланс)** — модуль
`src/core/pressure/MaterialBalanceDrift.ts`:

```
P_avg_new = P_avg_old - (N_p - N_inj) · B / (V_pore · c_t)
```

- `N_p`, `N_inj` — накопленные объёмы (reservoir m³).
- `V_pore = Σ_active(φ·h·dx·dy)` — суммарный поровый объём.
- `c_t = 1e-4 атм⁻¹` (дефолт).
- При VRR = 1 (добыча = закачка) P_avg не меняется (стационар).

**Свойства жидкостей** (упрощение): в текущей реализации
`μ_w·B_w ≠ μ_o·B_o`, но при расчёте давления и взаимного влияния
скважин используется **единый `μ·B`** (для упрощения: `μ_w·B_w`).
Это эквивалентно допущению «одинаковые свойства нефти и воды»,
которое делает модель «цветной жидкости».

**Насыщенность (на сетке)** — те же модули
`computeFluxes` (из `core/physics/DarcyFlux.ts`) и
`updateSaturation` (из `core/physics/SaturationSolver.ts`).
Потоки вычисляются из аналитического P (а не из CG-решения),
всё остальное (upwind, f_w, кламп) — без изменений. **Фронт
Бакли-Леверетта сохраняется** — насыщенность движется по сетке.

### 11.4. Pipeline (`core/time/SuperpositionStepper.ts`)

Один sub-step (dt — часы):
1. `solveRates(wells, pAvg, ...)` → `q_total` для каждой скважины
   (линейная система N×N).
2. `computeCellPressures(pAvg, q)` → `P_grid` (суперпозиция).
3. `splitRateByWaterCut(q, S_w_well)` → `qOil`, `qWater` для
   каждой скважины.
4. `computeFluxes(grid, T_g, P, S_w)` → `F_t`, `F_w`, `F_o`.
5. `updateSaturation(S_w, F, wellStates)` → `S_w^{n+1}`.
6. `pressureDriftStep(qProd, qInj, dt)` → `ΔP_avg`, обновляем
   `P_avg`.

CFL-адаптивный шаг: внутри `stepSuperposition()` несколько
sub-step'ов при необходимости.

### 11.5. Интеграция в `SimulationEngine`

`realStep()` в `src/app/SimulationEngine.ts` теперь вызывает
`stepSuperposition()`. Старый `step()` из `TimeStepper.ts`
сохранён (файл не удалён), но не используется в активном
pipeline. При необходимости — легко вернуть через флаг.

`pAvg`, `cum`, `poreVolumeM3` хранятся как поля движка.
`loadScenario` сбрасывает их.

## 12. Сводка зафиксированных решений

| Категория | Решение |
|---|---|
| Реализм | Учебный (корректная, но упрощённая физика) |
| Размерность | 2D сверху + динамические графики (cross-section — модуль сохранён) |
| Фазы | Oil + Water (двухфазная) — общий μ·B, модель «цветной жидкости» (v2) |
| Стек | Vanilla TypeScript + Canvas2D |
| Хостинг | Только локально, без CI, без remote |
| Язык UI | Русский |
| Единицы | Полевые метрические (мД, сП, атм, м³/сут, т/сут, ч) |
| Численный метод | **v2: Superposition (steady-state radial + superposition) + material balance**, насыщенность — upwind на сетке (как раньше) |
| Давление | Аналитика: `P(x) = P_avg + Σ (q·μB)/(2πkh) · ln(r/R_e)` (мгновенная стационарная воронка) |
| Взаимодействие скважин | Линейная система N×N: `A·q = (P_avg − P_bhp)`, N = число скважин |
| P_avg дрейф | Матбаланс: `ΔP_avg = -(N_p−N_inj)·B / (V_pore·c_t)`, `c_t = 1e-4 атм⁻¹` |
| Аквифер | Заменён дрейфом P_avg (v2); legacy `pAquiferAtm`/`aquiferTransmissibilityFrac` не используются |
| Гравитация | Нет (в MVP) |
| Капиллярное давление | Нет (в MVP), `P_c = 0` по построению (одинаковые свойства) |
| Многослойность | Нет (в MVP) |
| Default field | Синтетический (генератор с seed=42, K_MAX=2000 мД) |
| Rate limits | Producer 500, injector 2000 м³/сут. Ограничения **внутри** системы влияния (active set), знак `q` закреплён за типом скважины. Аварийный предел без лимита — 10 000 м³/сут |
| Save/Load | JSON v1, localStorage 3 слота + autosave + миграции (Phase 5) |
| Тесты | Unit (23 файла) + property (4) + integration (9) + e2e (1). 202/202 ✅ |
| Фазы | 9 фаз (0–8), Phase 0–4 ✅ done, Phase 5+ ⬜ (после стабилизации v2) |
