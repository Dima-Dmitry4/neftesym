8  Игра изнутри: архитектура для разработчика

neft = {
  const m = await import(new URL("assets/js/neft.js", document.baseURI).href);
  await m.ready();
  return m;
}
core = neft.core()

Эта глава – для тех, кто хочет не только играть, но и понимать код: проверять гипотезы, писать свои сценарии, искать ошибки и дорабатывать игру. Всё, что здесь описано, можно потрогать в живых ячейках.

8.1 Один файл – вся игра

Игра – один HTML-файл index.html (≈ 500 КБ) плюс локальная копия Plotly в vendor/. Сеть и сервер не нужны.

Часть Ответственность Правило
#sim-core физика, экономика, генерация объектов, эталоны, 101 самопроверка нет DOM: исполняется и в браузере, и в node
#wasm-accel горячие циклы на Rust: проводимости, давление, потоки, перенос генерируется rust/embed.mjs, руками не правится
#app интерфейс на Plotly, игровой цикл requestAnimationFrame нет физики

Разделение ядра и интерфейса – главное архитектурное решение: физику можно тестировать без браузера, а это пособие использует тот же #sim-core – скрипт сборки вырезает его из index.html перед каждым рендером.

8.2 API ядра

Ядро регистрирует себя как globalThis.OILCORE. Основные функции:

Функция Что делает
scenarioParams(id, seed) параметры объекта: вязкость, стоимость скважин, сейсмики
buildReservoir2(params) геология: k, кровля, толщины, ВНК, Sw0, разломы (tmE, tmN), разведка, сейсмика
createSim(r, params) состояние расчёта: P, Sw, скважины, экономика; методы addWell, setCompletion, convertWell, stimulate
advance(sim, days) цикл IMPES на days суток
solvePressure, transportSubstep, cflLimit шаги схемы по отдельности
krw, kro, fw, lambdaT, wellIndex физика из глав 3 и 5
solveEquipment, espHeadM, chokeDpAtm, PUMPS оборудование и узловой анализ
wellLog, pressureBuildup, interpretBuildup каротаж и ГДИС
createEconomy, flowOf, npvOf, scoreDevelopment деньги и оценка
cloneSim, yearlyFromSim клон для прогноза, годовые ряды
POLICIES, policyRun, REF эталоны
runSelfTests() все проверки

Список всего, что экспортирует ядро:

print(`Версия ядра ${core.VERSION}, ${neft.engineInfo()}`);
print(Object.keys(core).filter((k) => typeof core[k] === "function").sort().join(", "));

8.3 Ход расчёта: что делает advance

На каждом интервале давления (≤ 1 сут) ядро:

  1. applyEquipment – по режиму каждой скважины (ЭЦН, штуцер, КНС) находит забойное давление узловым анализом;
  2. solvePressure – решает неявное уравнение давления (CG или Rust-PCG), закрывая интервалы ствола с перетоком;
  3. computeFaceFluxes, updateWellRates – потоки через грани и дебиты по Писману;
  4. субшаги transportSubstep по условию CFL ровно до конца интервала;
  5. economy.update – натуральные единицы за шаг; recordHistory – посуточный снимок.

Посмотрим на всё это вживую – сколько итераций решателя и субшагов уходит на сутки:

const f = neft.field({ scenario: "bv8" });
f.drill({ x: 1000, y: 1000 });
f.drill({ x: 1300, y: 1000, type: "inj", choke: 20 });
const t0 = performance.now();
core.advance(f.sim, 30);
print(`30 суток за ${(performance.now() - t0).toFixed(0)} мс; итераций CG на последнем шаге: ${f.sim.lastCG.iters}`);
print(`CFL-предел шага переноса сейчас: ${core.cflLimit(f.sim).toFixed(3)} сут`);
return f.wellTable();

8.4 Ускоритель WebAssembly

Чтобы непрерывный режим («10 лет за 5 минут») не подтормаживал, горячие циклы переписаны на Rust (rust/src/lib.rs, структура Grid) и встроены в HTML как base64. JS-ядро вызывает их через setAccel; без WebAssembly тот же расчёт идёт на JS. Rust-решатель использует предобуславливатель DILU вместо Якоби – в 3–4 раза меньше итераций.

JS WebAssembly
одни игровые сутки, БВ8, 12 скважин 12,9 мс 2,35 мс
самотест в node 157 с 41 с
сверка: нефть за 2 года – совпадает до 4·10⁻⁴ %

Сравните сами (ускоритель можно временно выключить):

const run = () => {
  const f = neft.field({ scenario: "bv8" });
  for (let n = 0; n < 6; n++) f.drill({ x: 500 + 200 * n, y: 1000, type: n % 3 === 2 ? "inj" : "prod" });
  const t = performance.now(); core.advance(f.sim, 365);
  return { ms: performance.now() - t, oil: f.stats().cumOil_t };
};
const accel = globalThis.__oilAccel;
core.setAccel(null);  const js = run();
core.setAccel(accel); const wa = run();
print(`JS: ${js.ms.toFixed(0)} мс, WebAssembly: ${wa.ms.toFixed(0)} мс (×${(js.ms / wa.ms).toFixed(1)})`);
print(`нефть: ${js.oil.toFixed(1)} т против ${wa.oil.toFixed(1)} т`);

8.5 Детерминизм и сиды

Объект однозначно задаётся группой, сидом и размером сетки. Поэтому в геологии и эталонах запрещён Math.random: используется генератор mulberry32 с сидом от хеша hashSeed(группа, сид). Один сид у всего класса – одна и та же геология, одни и те же ошибки сейсмики и скины скважин.

8.6 Эталоны

Эталон канонического объекта найден оптимизатором (tools/search-reference.js): 22 процесса случайным восхождением перебирали параметры политики разработки – сетку и схему размещения, заканчивание, насосы, частоты, штуцеры, давления КНС и сбора, пороги перевода в ППД, ОПЗ, отключения – и максимизировали ту же оценку (50 % КИН + 50 % ЧДД за 20 лет). Найденная политика хранится в POLICIES, а годовые ряды – в REF. Для объектов по сиду эталон считается в фоне (Web Worker) той же политикой на шести вариантах расстановки.

Политику эталона можно прочитать как готовый совет по игре:

const names = { s: "шаг сетки, ячеек", pat: "схема (0 шахм., 1 «2:1», 2 ряды)", compl: "заканчивание", xf: "полудлина ГРП", hsL: "длина ГС",
  mgN: "стадий МГРП", f0: "частота ЭЦН", dInj: "штуцер нагнет., мм", kns: "давление КНС", pg: "давление сбора", pre: "лет нагнет. на нефти", shut: "отключать нерентаб." };
for (const [id, P] of Object.entries(core.POLICIES))
  print(`${core.SCENARIOS[id].short}: ` + Object.entries(names).map(([k, n]) => `${n} = ${P[k]}`).join("; "));

8.7 Самотест

101 автоматическая проверка (runSelfTests) – балансы, аналитика, детерминизм, эталоны. Перед каждым изменением физики их запускают:

node tests/selftest.js            # ≈ 3–4 мин на JS
node tests/selftest.js --wasm     # ≈ 1 мин через WebAssembly + сверка JS = WASM

Несколько быстрых групп можно прогнать прямо здесь:

const groups = ["relPermTests", "wellTests", "economyTests"];
for (const g of groups) for (const t of core[g]()) print(`${t.pass ? "✔" : "✘"} ${t.name}${t.details ? " – " + t.details : ""}`);

8.8 Находка этого пособия

При подготовке главы 4 выяснилось, что строгая проверка пересечения отрезков (segCross) оставляла щели в «запечатанных» разломах канонических объектов (Глава 4, врезка «Находка»). Это типичная ошибка, которую ловят численным опытом, а не чтением кода: сравнили запечатанный и проницаемый разлом – а разницы почти нет. В игре её исправили так, как и положено: segCross учитывает касание, в level2bTests добавлена проверка (щелей нет, перетока через F-1 нет), эталоны найдены заново. Старое поведение можно воспроизвести: neft.field({ strictGaps: true }).

8.9 Задания

  1. Измерьте, сколько итераций CG уходит на сутки при сетке 25, 50 и 100. Как это согласуется с оценкой O(N^3) из окна «⚙ Расчёт»?
  2. Найдите в выводе первой ячейки функцию, которая считает скин трещины, и проверьте её против формулы из Глава 5.
  3. Напишите в живой ячейке свою «политику»: сетку скважин по заданному шагу на БВ8 и сравните ЧДД с эталоном (≈ 8,6 млрд руб).
