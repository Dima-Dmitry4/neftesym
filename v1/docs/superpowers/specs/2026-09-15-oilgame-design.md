# Дизайн: учебная игра «Разработка нефтяного месторождения» (oilgame)

Дата: 2026-09-15
Статус: согласован с заказчиком (единицы, экономика, алгоритм IMPES с непрерывной Sw)

## 1. Цель и рамки

Учебная игра-симулятор разработки нефтяного месторождения в одном HTML-файле (`index.html`),
без внешних зависимостей и сети (оффлайн), вся графика — Canvas 2D, интерфейс на русском.

Игрок бурит добывающие и нагнетательные скважины, задаёт забойные давления (Pwf), наблюдает
карты давления и насыщенности, графики разработки и экономический результат. Физика — упрощённый
двухфазный (нефть/вода) IMPES-симулятор в 2D с поршневым вытеснением. Назначение — обучение:
основные вещи физичны, второстепенные упрощены.

**Не входит (осознанно):** газовая фаза, растворённый газ, трёхмерность, трещиноватость,
гидроразрыв, капиллярные силы, гравитация, многослойность, сеточные зависимости высокого порядка.

## 3. Физическая модель

### 3.1 Сетка и геология

- Поле 2×2 км, равномерная сетка 50×50, ячейка 40×40 м (~1500 активных ячеек внутри контура).
- Контур нефтеносности — неровная замкнутая кривая (эллипс с гармоническими возмущениями);
  ячейки вне контура неактивны.
- Толщина пласта h = 10 м (постоянная), пористость φ = 0.2 (постоянная).
- Карта проницаемости: детерминированный seed (mulberry32); логнормальный фон 20–150 мД
  + синусоидальный руслообразный канал 300–800 мД, протягивающийся через поле.
- Запасы: OOIP = Σ_active(dx·dy·h·φ·(1−Swc)) ≈ 4 млн м³ ≈ 3.4 млн т.

### 3.2 Флюиды и свойства

| Параметр | Значение | Настраивается |
|---|---|---|
| Начальное давление P₀ | 250 атм | нет |
| Вязкость нефти μ₀ | 5 сП | да (перед стартом, 1–50 сП) |
| Вязкость воды μ_w | 1 сП | нет |
| Связанная вода Swc | 0.2 | нет |
| Остаточная нефть Sor | 0.25 | нет |
| Общая сжимаемость c_t | 1e-4 1/атм | нет |
| Плотность нефти ρ | 0.86 т/м³ | нет |

### 3.3 Давление — неявная схема (ядро IMPES)

Несжимаемые флюиды + упругость пласта, двухточечная аппроксимация потоков (TPFA, 5-точечный
шаблон), одна сетка для давления и насыщенности:

```
Σ_f T_f · (P_nb − P_i) + q_i = Vp,i · c_t · (P_i^{n+1} − P_i^n) / Δt
```

- Проводимость на грани: `T_f = (h · Δ/Δ) · k_harm · λ_t^up`, где k_harm — гармоническое среднее
  проницаемостей соседей, λ_t^up = krw(Sw_up)/μ_w + kro(Sw_up)/μ_o — тотальная подвижность
  с upstream-ячейки, замороженная с прошлого шага (классический IMPES).
- Скважинный член q_i — см. 3.5.
- Решатель: матрично-свободный метод сопряжённых градиентов (CG), диагональный preconditioner,
  warm start от прошлого решения, критерий |r|/|r₀| < 1e-6, лимит 500 итераций. Матрица SPD
  (гармоническое усреднение). Давление пересчитывается раз в игровой сутки.
- Оценка стоимости: ~1500 ячеек × 30–80 итераций × ~10 флопов ≈ 1–2 мс на решение — с запасом
  для скорости ×50 даже на слабом компьютере.
- Отвергнутые альтернативы: плотный LU (~10¹⁰ флопов — неприемлемо), SOR (медленнее CG с
  warm start).

### 3.4 Насыщенность — явная схема, поршневое вытеснение

Линейные («поршневые») фазовые проницаемости:

```
krw = (Sw − Swc) / (1 − Swc − Sor)        при Sw > Swc, иначе 0
kro = (So − Sor) / (1 − Swc − Sor)        при So > Sor, иначе 0
```

Перенос воды upstream по тотальному потоку из решения по давлению:

```
Sw_i^{n+1} = Sw_i^n + (Δt/Vp,i) · ( Σ_{f,вх} u_f·fw(Sw_up)  −  Σ_{f,вых} u_f·fw(Sw_i)  +  q_w,i )
fw(Sw) = (krw/μ_w) / (krw/μ_w + kro/μ_o)
```

где u_f ≥ 0 — тотальный поток через грань (м³/сут, из решения по давлению), q_w,i — источник
воды в ячейке: +q для нагнетательной, −q·fw(Sw_i) для добывающей. Насыщенность нефти
So = 1 − Sw отслеживается неявно.

- Консервативно по построению (вода считается из тех же тотальных потоков, что и давление).
- Фронт резкий (2–4 ячейки); при M = μ₀/μ_w > 1 физично распластывается — прорыв воды виден
  как плавный рост обводнённости добывающей скважины от 0.
- Шаг ограничен CFL: `Δt ≤ 0.25 · min_i (Vp,i / Σ_in |u_f|)` по активным ячейкам, плюс кап
  Δt ≤ 2 сут. Игровой шаг делится на субшаги по CFL; насыщенность считается на каждом субшаге,
  давление — раз в сутки (стандартная IMPES-практика).
- Клампы Sw в [Swc, 1−Sor]; закачка воды входит в баланс ячейки скважины как источник.

### 3.5 Скважины — формула Писмана

```
q_жидк = WI · λ_t,cell · (P_cell − P_wf)        [м³/сут]
WI = 2π·k·h / ln(re/rw),  re = 0.2·Δ,  rw = 0.1 м,  skin = 0
```

- Добывающая: q ≥ 0 (кламп направления). Дебит нефти q_o = q · λ_o/λ_t, воды q_w = q · λ_w/λ_t
  по насыщенности ячейки. Отображение: q_o в т/сут (×0.86), q_w в м³/сут.
- Нагнетательная: q ≤ 0 (кламп), вся закачка — вода, м³/сут.
- Pwf задаётся игроком слайдером при размещении и может меняться на ходу:
  добывающие 1–0.9·P₀ атм (1–225), нагнетательные P₀–1.5·P₀ атм (250–375).
  Значения по умолчанию: добывающая 150 атм, нагнетательная 325 атм.
- В одной ячейке — не более одной скважины. Бурение мгновенное (упрощение), деньги списываются
  сразу.

### 3.6 Балансные соотношения (для валидации)

- Упругий запас: Σ q·Δt = Σ Vp·c_t·(P̄ − P₀) в закрытой системе без закачки (материальный баланс).
- Вода: накопленная закачка = прирост запасов воды в пласте + накопленная добыча воды.

## 4. Экономика

| Статья | Значение по умолчанию | Настраивается |
|---|---|---|
| Цена нефти (netback) | 10 000 руб/т | да |
| Бурение скважины | 10 млн руб | да |
| Подъём жидкости | 500 руб/м³ | да |
| Закачка воды | 300 руб/м³ | да |
| Стартовый капитал | 50 млн руб | да |
| Горизонт игры | 10 лет | да |

- Баланс(t) = капитал + Σ(выручка − подъём − закачка) − Σ(бурение); начисление непрерывно по dt.
- Уйти в минус можно (баланс красным, игра продолжается) — игрок видит последствия.
- Итоговые KPI: накопленная добыча нефти (т), % извлечения от OOIP, конечный баланс (млн руб),
  накопленные вода и закачка (м³), средняя обводнённость, среднее давление, число скважин.

Баланс замысла: при цене подъёма 500 руб/м³ и закачки 300 руб/м³ экономика игры
сосредоточена на управлении обводнённостью — ранняя закачка поддерживает давление,
но прорыв воды к добывающим резко увеличивает расходы.

## 5. Интерфейс

### 5.1 Экраны

1. **Настройки** (перед стартом): карта месторождения (слой проницаемости), параметры
   (μ₀, цена нефти, бурение, подъём, закачка, горизонт, капитал) с значениями по умолчанию,
   кнопка «Начать», кнопка «Самотест» (запуск проверок из раздела 7).
2. **Игра** — см. 5.2.
3. **Итоги** (по достижении горизонта): KPI-таблица, итоги по скважинам, кнопки
   «Продолжить (песочница)» и «Начать заново».

### 5.2 Экран игры

- **Верхняя панель:** дата (прошло / осталось), текущий баланс в млн руб (и ± за последний
  месяц), кнопки пауза / ×1 / ×10 / ×50, кнопка «Итоги» (после горизонта).
  Скорости: пауза; ×1 = 2 сут/с; ×10 = 20 сут/с; ×50 = 100 сут/с (10 лет за ~37 с).
- **Слева — карта** (canvas ~600×600): переключатель слоя «Проницаемость / Давление /
  Насыщенность»; цветовая шкала с min/max; контур нефтеносности; скважины: добывающая — кружок,
  нагнетательная — треугольник, подпись; каждой скважине назначается свой цвет (используется и
  на графиках). Hover по ячейке — подсказка (k, P, Sw).
- **Бурение:** кнопки-инструменты «Добывающая» / «Нагнетательная» → клик по активной ячейке
  → списание денег, скважина сразу в работе. Неактивная ячейка или занятая — сообщение.
- **Панель скважин** (под картой или справа, таблица): имя, тип, Pwf-слайдер + число,
  текущие q_нефти (т/сут), q_воды (м³/сут), обводнённость (%).
- **Справа — 5 графиков** (canvas ~380×160, подписи осей и единицы):
  1. Дебит нефти по скважинам — слоистый (stacked area, т/сут), цвет каждой скважины;
  2. Среднее пластовое давление (атм), пунктиром P₀;
  3. Забойные давления (атм) — по линии на скважину;
  4. Накопленная добыча нефти (т);
  5. Баланс денег (млн руб), вертикальные отметки бурений.
- История для графиков пишется раз в игровые сутки.

## 6. Архитектура кода (один файл)

| Модуль (класс/объект) | Ответственность |
|---|---|
| `rng`, `params` | ГПСЧ (mulberry32, фикс. seed), все параметры |
| `Reservoir` | сетка, активные ячейки, k/φ/h, контур, OOIP |
| `Wells` | список скважин (i, j, тип, Pwf), цвета, дебиты |
| `Simulator` | IMPES-шаг: давление (CG), насыщенность (upwind), CFL-субшаги |
| `Economy` | баланс, накопленные показатели, история |
| `Renderer` | карта (слои k/P/Sw), скважины, шкала, hover |
| `Charts` | 5 графиков |
| `Game` | цикл requestAnimationFrame, скорость/пауза, события мыши, экраны |

Поток данных: `Game` (ввод, скорость) → `Simulator.advance(сутки)` → `Economy.update` →
`Renderer`/`Charts` (перерисовка кадра). Состояние экранов: настройки → игра → итоги.

## 7. Валидация (встроенный «самотест»)

Проверки запускаются скрытой симуляцией и печатают отчёт (все должны проходить):

1. Без скважин: P и Sw неизменны (дрейф < 0.01 атм, < 1e-6).
2. Материальный баланс: суммарный отбор = упругий запас, погрешность < 1%.
3. Закачка = отбор: среднее давление стабилизируется (дрейф < единиц атм/год).
4. Одна добывающая без закачки: падение среднего давления соответствует аналитике
   материального баланса; стартовый дебит соответствует формуле Писмана.
5. Сохранение массы воды: закачано = прирост запаса + добыто, погрешность < 0.1%.
6. Время прорыва: линия нагнетательная → добывающая, прорыв ≈ поровый объём между ними /
   расход (точность по порядку величины).

## 8. План разработки по шагам

1. Каркас HTML/CSS, три экрана, игровой цикл rAF со скоростями и паузой.
2. Геология: генерация сетки, карты k, контур; отрисовка слоёв карты, шкала, hover.
3. Давление: сборка потоков, решатель CG; тест стационара (одна добывающая).
4. Скважины: модель Писмана, размещение мышью, слайдеры Pwf, панель скважин.
5. Насыщенность: явный перенос, CFL-субшаги, карта насыщенности, обводнённость.
6. Экономика: баланс, накопленные показатели.
7. Графики: 5 canvas-графиков с историей по суткам.
8. Экран настроек и итоговый экран.
9. Самотест (раздел 7), балансировка экономики, полировка UI.

## 9. Риски и упрощения

- Численная диффузия фронта (2–4 ячейки) — приемлемо для учебной цели.
- При очень агрессивной закачке CFL может уменьшать субшаги до долей суток — производительности
  хватает (оценка в 3.3/3.4), худший случай проверяется в самотесте по времени шага.
- Экономический баланс («пропорционально» якорям заказчика) подобран из разумных соотношений
  и уточняется на шаге 9.
