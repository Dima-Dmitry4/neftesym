# AGENTS.md — инструкции по репозиторию

Техническое руководство по проекту **ressim_prototypes** для разработчиков и
ИИ-агентов. Пользовательское описание проекта — в [`README.md`](README.md).

## Что это

Набор учебных прототипов расчётных модулей для гидродинамического моделирования
фильтрации нефти в пористой среде. Цель — приложения и игры для студентов.
Каждый прототип это **один автономный HTML-файл на чистом JavaScript** (Vanilla
JS, ES2020, Canvas 2D), который работает оффлайн прямо из файловой системы:
**никаких внешних зависимостей, CDN, npm и сетевых запросов** (допускаются локальные копии библиотек в `vendor/` внутри папки прототипа: d3-delaunay в v3_pebi, Plotly в v1).

Отдельный прототип = отдельная папка со своим `index.html`. Прототипы друг от
друга не зависят; всё нужное для каждого лежит внутри папки прототипа. V1 и
V3 — полностью автономные single-HTML, не требуют сборки. **V2** — единственное
исключение: это проект на TypeScript, который собирается в
`v2/standalone/oilgame.html` (см. ниже).

## Команды

```bash
node tests/check-prototypes.js   # реестр: обязательные поля, уникальность id, наличие файлов
node v1/tests/selftest.js        # самотест ядра физики прототипа v1
node v3_pebi/tests/run.js        # тесты ядра физики прототипа v3_pebi (53 проверки)

# Прототип v2 — TypeScript, требует npm + node ≥ 20. Артефакт —
# v2/standalone/oilgame.html: именно его открывает карточка в меню и
# именно он публикуется на pages. Перед коммитом правок в v2/src
# пересоберите standalone.
cd v2
npm install                       # ~127 MB, ~6 700 файлов → в .gitignore
npm run typecheck                 # tsc --noEmit (+ tests config)
npm run lint                      # eslint .
npm test                          # vitest (36 файлов / 202 теста)
npm run standalone                # tsc + vite build + inline → standalone/oilgame.html

python3 -m http.server 8000      # локальный статический сервер (если нужен), затем http://localhost:8000/
```

Скрипты `tests/check-prototypes.js`, `v1/tests/selftest.js` и
`v3_pebi/tests/run.js` не требуют зависимостей (только стандартная
библиотека Node ≥ 18). Тесты v2 (`npm test`) требуют `node_modules`
виртуэстана в `v2/`.

## Соглашения по прототипам

- **Автономность.** Один прототип — один `index.html` (или артефакт сборки
  `standalone/<game>.html`); никаких CDN и сетевых запросов. Допустимы
  отдельные `.js`/`.css` рядом, но приложение должно работать и при открытии
  файла напрямую (`file://`).
- **Единый вход.** Точка входа прототипа называется `index.html`
  (для v1/v3) **или** `standalone/<game>.html` (для TS-проектов вроде v2).
  Имя папки — короткое и говорящее (`waterflood/`, `welltest/`, …).
- **Проверяемость.** Физику выносите в чистое ядро (без DOM) и пишите самотест —
  либо кнопкой «самотест» в интерфейсе, либо node-харнессом, который извлекает
  ядро из HTML и сверяет с аналитическими решениями (v1, v3_pebi).
  Для TS-прототипов — vitest (см. v2).
- **Единицы.** Практические метрические: давление — атм, проницаемость — мД,
  вязкость — сП, дебит/объём — м³/сут и м³, время — сут (для v1/v3) или ч
  (для v2), нефть — т при выводе.
- **Язык интерфейса** — русский.
- **Относительные пути.** Все ссылки и подключения внутри прототипа и меню —
  относительные (сайт публикуется из подпапки `/ressim_prototypes/`).

### Исключение для v2 (TS-проект, требующий сборки)

V2 — единственный прототип, который не помещается в один
самодостаточный HTML без сборки: у него TypeScript + Vite + 60+ модулей,
200+ тестов. Решение — собрать его в **однофайловый standalone HTML**:

1. `cd v2 && npm install` (≈127 MB; в `.gitignore`).
2. Правки в `src/` → `npm run typecheck && npm run lint && npm test`.
3. `npm run standalone` → `v2/standalone/oilgame.html` (≈76 КБ,
   весь JS+CSS инлайн).
4. Закоммитьте обновлённый `v2/standalone/oilgame.html` вместе
   с правками в `src/`.

`oilgame.html` — это и есть «точка входа», и именно её карточка
открывает в корневом меню (`path: "v2/standalone/oilgame.html"`).
Vite-сборка `v2/dist/` — **не** артефакт публикации: она только
промежуточная для `build-standalone.mjs` и в `.gitignore`.

## Как добавить новый прототип

1. Создайте папку с коротким говорящим именем, например `waterflood/`.
2. Положите в неё автономный `index.html` — один файл, без внешних зависимостей
   и обращений к сети. Ядро расчёта отделяйте от интерфейса так, чтобы кнопка
   «самотест» (или отдельный `tests/`) могла проверить физику.
3. Допишите запись в `prototypes.js` (массив `prototypes`).
4. Проверьте реестр: `node tests/check-prototypes.js` — все проверки должны
   пройти (id уникальны, файлы по `path` и `links` существуют).
5. Откройте корневой `index.html` и убедитесь, что карточка появилась и ведёт
   куда нужно.

## Реестр `prototypes.js`

Файл экспортирует объект `{ schema, prototypes }`. В браузере он доступен как
`window.PROTOTYPES`, в node — через `require`, поэтому его можно проверять и
использовать в скриптах. Меню строит список из этого файла: поиск (по названию,
описанию, тегам) и фильтр по тегам появляются автоматически по мере добавления
записей — отдельно настраивать нечего.

Поля записи:

| Поле | Обяз. | Назначение |
|---|---|---|
| `id` | да | Короткий уникальный идентификатор (обычно имя папки) |
| `title` | да | Название прототипа |
| `subtitle` | нет | Краткая строка под заголовком (технология/тема) |
| `description` | нет | Пара предложений: что делает и чему учит |
| `path` | да | Путь к точке входа, относительно корня (например `v1/index.html`) |
| `tags` | да | Массив строк для поиска и фильтра по тегам |
| `status` | да | Одно из: `готов`, `в работе`, `черновик`, `идея` |
| `added` | нет | Дата добавления `ГГГГ-ММ-ДД` |
| `links` | нет | Массив `{ label, path }` — доп. материалы (спека, план, тесты) |

Пример:

```js
{
  id: "waterflood",
  title: "Заводнение — вытеснение нефти водой",
  subtitle: "1D Бакли–Леверетт с фронтом",
  description: "Наглядно показывает формирование фронта вытеснения и обводнённость.",
  path: "waterflood/index.html",
  tags: ["1D", "заводнение", "Бакли–Леверетт"],
  status: "в работе",
  added: "2026-10-11",
}
```

## Прототип v1 — внутреннее устройство

`v1/index.html` состоит из двух скриптов:

| Скрипт | Ответственность |
|---|---|
| `#sim-core` | Чистое ядро без DOM: параметры и ГПСЧ, геология (`buildReservoir`), ОФП/`fw`/`WI`, давление (`solvePressure`, CG), перенос насыщенности (`transportSubstep`, CFL), скважины (`updateWellRates`), полный цикл (`advance`), экономика (`createEconomy`), самотесты (`runSelfTests`). Регистрируется в `globalThis.OILCORE`. |
| `#app` | Интерфейс: рендер карты и шкалы, пять графиков, экраны и игровой цикл `requestAnimationFrame`, бурение, слайдеры Pwf, итоги. |

Разделение позволяет исполнять ядро в node и проверять физику без браузера:
`v1/tests/selftest.js` вырезает `#sim-core` из HTML, загружает его как модуль и
вызывает `OILCORE.runSelfTests()`. Тот же набор (52 проверки, из них 28 — уровень 2 и оборудование) прогоняется в
браузере кнопкой «Самотест физики». Физическая модель, единицы и формулы описаны
в [`v1/README.md`](v1/README.md) и в спецификации `v1/docs/superpowers/specs/`.

Правила для этого прототипа: единый источник истины — `index.html`; при правке
физики обновляйте и самотесты, и `v1/README.md` при изменении модели.

## Прототип v2 (Oilgame) — внутреннее устройство

`v2/` — обычный TypeScript-проект (Vite + Vitest + ESLint + Prettier),
≈60 модулей в `src/core/*` и `src/ui/*`, ≈37 файлов тестов. Подробная
инструкция по структуре, соглашениям и численным конвенциям — в
[`v2/AGENTS.md`](v2/AGENTS.md). Очень краткая выжимка:

| Подсистема | Где |
|---|---|
| Чистое ядро (grid/properties/physics/wells/pressure/time/state/economics) | `src/core/` |
| UI (Canvas2D MapView, ChartsPanel, WellsList, TopBar, StatusBar) | `src/ui/` |
| Связка UI ↔ симулятор + EventBus | `src/app/` |
| Пресеты (5-spot, channel, faultBlock, …) | `src/data/presets/` |
| Headless-прогон симулятора (`npm run sim`) | `src/cli/simCli.ts` |
| Стабилизация v2: rate relaxation, P_avg damping, CFL по ячейкам | `src/core/time/SuperpositionStepper.ts`, `core/wells/RateSolver.ts` |

**Поток сборки и публикации:** правки в `src/` проверяются через
`npm run typecheck && npm run lint && npm test` (202/202 должны
быть зелёные — иначе изменения небезопасны). После этого —
`npm run standalone`: TypeScript-проверка → Vite-сборка `dist/` →
Node-скрипт `scripts/build-standalone.mjs` инлайнит JS+CSS в
`v2/standalone/oilgame.html`. Этот файл коммитится и публикуется.
Карточка в корневом меню открывает именно его.

## Определение готовности (перед коммитом)

1. `node tests/check-prototypes.js` — без ошибок.
2. Для затронутых автономных прототипов — их самотесты (например
   `node v1/tests/selftest.js`, `node v3_pebi/tests/run.js`) проходят полностью.
3. Для v2: `cd v2 && npm run typecheck && npm run lint && npm test`
   (36 файлов / 202 теста зелёные).
4. Артефакт сборки v2 в актуальном состоянии: если правили `v2/src/`,
   выполните `npm run standalone` и закоммитьте свежий
   `v2/standalone/oilgame.html`.
5. Прототип открывается двойным щелчком (проверить работу оффлайн).
6. Обновлено описание прототипа (`<прототип>/README.md`) и, при необходимости,
   корневой `README.md` и запись в `prototypes.js`.

## Публикация веб-версии (GitVerse Pages)

Сайт публикуется из ветки **`pages`** (GitVerse Pages → источник «Ветка»). Так как
проект целиком состоит из готовой статики, в корне лежит файл **`.nojekyll`** — он
отключает сборку через Jekyll, и файлы публикуются как есть (без преобразования
Markdown и Liquid). Все ссылки относительные, поэтому сайт корректно работает из
подпапки (`/ressim_prototypes/`).

Адрес: <https://khabibullinra.gitverse.site/ressim_prototypes/>

`master` — рабочая ветка (источник), `pages` — публикуемая копия (прямое зеркало
`master`). После изменений в `master` обновите публикацию:

```bash
git switch master
# ... правки, проверки, коммит ...
git branch -f pages master     # зеркалим master в pages
git push origin master pages   # Pages пересобирается автоматически на пуш в pages
```

Первые запросы после пуша могут отдавать 404 — сборка и публикация **ленивые**
(асинхронные) и **могут занимать несколько минут**. **Не ждите и не опрашивайте
рендеринг**: после пуша в `pages` сборка запускается сама, проверять её готовность
из терминала не нужно. Статус и логи — в **Настройки → Страницы** (workflow
`pages-build-deploy`).

## Стиль

- Сообщения коммитов — conventional commits, по-русски допустимо
  (`feat:`, `fix:`, `test:`, `docs:`), с областью для прототипа: `feat(v1): ...`.
- Комментарии в коде — по-русски, по делу; формулы и единицы указывать рядом.
- Не добавлять зависимости и сборку: всё должно работать из файла напрямую.
